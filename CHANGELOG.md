# Changelog

## 0.1.1 — 2026-10-22

- The Free-tier upgrade note and `--help` link to the GitHub README (`https://github.com/sherzodmax/framedrift#free-and-pro`), not to npmjs.com: the npm package does not exist yet, so that link was a 404.
- Repo CI is green on GitHub's ubuntu runners: the e2e "Figma render" stand-in is now rendered on the machine running the e2e instead of being a committed PNG. The committed one had the dev machine's `system-ui` font (Noto Sans) baked in, so on a runner, where `system-ui` is another font, a matching page showed 1.36% drift (check 4) and the size-mismatch case 24.29% (check 9). framedrift itself was not at fault: stock Google Chrome and Playwright's Chromium render the page identically on the same machine.
- Capture no longer crashes on a page that navigates again right after it loads (a script redirect to `/login`, an auto-submitted form): it used to fail every time with `page.addStyleTag: Execution context was destroyed`, and the R4-01 header test hit the same race on a CI runner. framedrift now waits for the page it lands on, applies its styles and `--hide` there, and stops with "The page kept navigating after it loaded" if the page never settles.
- The launch-config self-test reads the nested `node --test` run as TAP, so it also passes on Node 24 (whose default reporter has no `# fail 0` line).
- README "Known limitations → Fonts": generic families (`system-ui`, `sans-serif`) resolve to whatever font the CI machine has.

## 0.1.0 — 2026-10-22

First version.

- `framedrift compare`: capture any URL with headless Chromium and diff it against a Figma frame (or a local PNG). Self-contained HTML report (side-by-side, overlay, swipe, diff), `results.json`, `summary.md`.
- Hotspots: differing regions are grouped and labelled with the Figma layer they fall on ("Button / Sign in (Button / Variant=Primary)").
- `framedrift run`: many frames from `.framedrift.json` and/or `framedrift:` lines in the PR description.
- GitHub Action (composite): runs on `deployment_status` from Vercel, uploads the report as an artifact, posts and updates one PR comment.
- Vercel Deployment Protection bypass support. The bypass secret and `--header` values are added only to requests for the preview base URL's origin (scheme, host and port), including each same-origin redirect hop for any method (a non-GET request answered 303, or a POST answered 301/302, continues as a GET without a body, as in the Fetch standard, and stays a GET without a body for every later hop, 307/308 included, same-origin or not, as in Chromium; a 307/308 on a request that was never rewritten keeps its method and body). They are not added to third-party requests or to cross-origin redirect targets. Frame paths must stay on that origin (`/login`; `.framedrift.json` and the PR description accept root-relative paths only, the library's `joinUrl` also accepts same-origin absolute URLs). The bypass secret is only sent over https on the default port, to the Vercel project's own preview hosts when `vercel-project` / `vercel-team` (CLI `--vercel-project` / `--vercel-team`) are set (`<project>-<9-character hash>-<team>.vercel.app` and `<project>-git-<branch>-<team>.vercel.app`), to exactly the `preview-hosts` input / `--preview-host` list when that is set, and otherwise to any `*.vercel.app` host with a warning. On a `deployment_status` event (also with `preview-url` set), that status must have been created by a login in the `trusted-deployment-creators` input (default `vercel[bot]`, Vercel's GitHub integration), else the run fails without sending it. `vercel-project` without `vercel-team` fails the check when a bypass secret is set (the patterns would match a project of that name in any team) and is a warning otherwise. The preview base URL can't be a loopback (except on the CLI or with `allow-loopback-preview`), link-local or cloud-metadata address. Limits: service workers are blocked while headers are set, and a same-origin redirect inside an iframe is followed by framedrift and served under the original URL.
- Any failed comparison (preview HTTP error, Figma error, rejected frame) fails the run: `framedrift run` exits 3 and the Action gate is `error`, even if other frames were clean.
- Action input `figma-files`: allowlist of Figma file keys a repo may render.
- framedrift Pro via Polar license keys: unlimited frames and failing the check. Until Polar is configured, every run is Free and keys are ignored (logged, never an error).
- `framedrift demo`: full comparison on a built-in fixture page, no Figma token or network needed.
- Clear one-line errors for unreachable previews (connection refused, DNS, timeouts), missing selectors, Figma 403/404 and long rate-limit waits (fails fast instead of sleeping in CI).
- A malformed `--header` (no `Name:`) is reported by position (`Invalid header #2`); no part of it is printed, since it is often a bare token.
- Usage errors exit 2: missing Figma token, invalid `--fail-on` / `--threshold` / `--scale` / `--viewport`, missing config file. Invalid Action inputs fail the step with an explanation.
- `.framedrift.json` frames can use a local `design` PNG (resolved relative to the config file).
- PR comment treats frame names, paths, Figma layer text and errors as plain text (no table breaks, @mentions, HTML, Markdown links or GitHub autolinks of bare `https://…` / `www.` text), and only links our own http(s) URLs (Figma frame, preview).
- One redactor for every output (PR comment, `index.html`, `results.json`, `summary.md`, `notes.json`, step summary, Action outputs and the log): URL userinfo, secret-looking query values (`token`, `x-vercel-protection-bypass`, `_vercel_share`, `code`, `otp`, …, also percent-encoded several times), `Bearer` / `Basic` / `Digest` credentials (also percent-encoded; a plain word after `Bearer` or `Basic` is left alone), secret `Name: value` headers (`Authorization`, `Cookie`, `X-Api-Key`, `…-Key`, …; the value stops at a ` |` table border, so summary rows stay whole) and the bypass / `--header` values are replaced with `REDACTED`, in URLs, frame names, paths and error messages, and in every line the CLI prints (paths are redacted for display only; files are read and written at the real path, so `--out 'out?token=…'` works).
- The Action fails (gate `error`) when there is nothing to compare or the `config` input points at a missing file; unusable `framedrift:` lines in the PR description are logged as warnings.
- The sticky PR comment is matched to the exact identity of the token (PAT user, or the app bot via GraphQL `viewer`, else `github-actions[bot]`), never to any bot.
- `runFrames` validates `failOn` / `threshold` (options, `defaults` and per-frame) like the CLI does.
- `failOn` / `threshold` in `.framedrift.json` are validated (a typo is a config error, exit 2). Precedence: frame > CLI flag / Action input > `defaults` > built-in.

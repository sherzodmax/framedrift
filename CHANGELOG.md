# Changelog

## 0.1.0 — unreleased

First version.

- `framedrift compare`: capture any URL with headless Chromium and diff it against a Figma frame (or a local PNG). Self-contained HTML report (side-by-side, overlay, swipe, diff), `results.json`, `summary.md`.
- Hotspots: differing regions are grouped and labelled with the Figma layer they fall on ("Button / Sign in (Button / Variant=Primary)").
- `framedrift run`: many frames from `.framedrift.json` and/or `framedrift:` lines in the PR description.
- GitHub Action (composite): runs on `deployment_status` from Vercel, uploads the report as an artifact, posts and updates one PR comment.
- Vercel Deployment Protection bypass support. The bypass secret and `--header` values are added only to requests for the preview base URL's origin (scheme, host and port), including each same-origin redirect hop for any method (a non-GET request answered 303, or a POST answered 301/302, continues as a GET without a body, as in the Fetch standard, and stays a GET without a body for every later hop, 307/308 included, same-origin or not, as in Chromium; a 307/308 on a request that was never rewritten keeps its method and body). They are not added to third-party requests or to cross-origin redirect targets. Frame paths must stay on that origin (`/login`; `.framedrift.json` and the PR description accept root-relative paths only, the library's `joinUrl` also accepts same-origin absolute URLs). The bypass secret is only sent over https on the default port, to the Vercel project's own preview hosts when `vercel-project` / `vercel-team` (CLI `--vercel-project` / `--vercel-team`) are set (`<project>-<9-character hash>-<team>.vercel.app` and `<project>-git-<branch>-<team>.vercel.app`), to exactly the `preview-hosts` input / `--preview-host` list when that is set, and otherwise to any `*.vercel.app` host with a warning. When the preview URL comes from a `deployment_status` event, that status must have been created by `vercel[bot]` (Vercel's GitHub integration), else the run fails without sending it. The preview base URL can't be a loopback (except on the CLI or with `allow-loopback-preview`), link-local or cloud-metadata address. Limits: service workers are blocked while headers are set, and a same-origin redirect inside an iframe is followed by framedrift and served under the original URL.
- Any failed comparison (preview HTTP error, Figma error, rejected frame) fails the run: `framedrift run` exits 3 and the Action gate is `error`, even if other frames were clean.
- Action input `figma-files`: allowlist of Figma file keys a repo may render.
- framedrift Pro via Polar license keys: unlimited frames and failing the check. Until Polar is configured, every run is Free and keys are ignored (logged, never an error).
- `framedrift demo`: full comparison on a built-in fixture page, no Figma token or network needed.
- Clear one-line errors for unreachable previews (connection refused, DNS, timeouts), missing selectors, Figma 403/404 and long rate-limit waits (fails fast instead of sleeping in CI).
- Usage errors exit 2: missing Figma token, invalid `--fail-on` / `--threshold` / `--scale` / `--viewport`, missing config file. Invalid Action inputs fail the step with an explanation.
- `.framedrift.json` frames can use a local `design` PNG (resolved relative to the config file).
- PR comment treats frame names, paths, Figma layer text and errors as plain text (no table breaks, @mentions, HTML, Markdown links or GitHub autolinks of bare `https://…` / `www.` text), and only links our own http(s) URLs (Figma frame, preview).
- One redactor for every output (PR comment, `index.html`, `results.json`, `summary.md`, `notes.json`, step summary, Action outputs and the log): URL userinfo, secret-looking query values (`token`, `x-vercel-protection-bypass`, `_vercel_share`, `code`, `otp`, …, also percent-encoded several times), `Bearer` / `Basic` credentials, secret `Name: value` headers (`Authorization`, `Cookie`, `X-Api-Key`, …) and the bypass / `--header` values are replaced with `REDACTED`, in URLs, frame names, paths and error messages, and in every line the CLI prints (paths are redacted for display only; files are read and written at the real path, so `--out 'out?token=…'` works).
- The Action fails (gate `error`) when there is nothing to compare or the `config` input points at a missing file; unusable `framedrift:` lines in the PR description are logged as warnings.
- The sticky PR comment is matched to the exact identity of the token (PAT user, or the app bot via GraphQL `viewer`, else `github-actions[bot]`), never to any bot.
- `runFrames` validates `failOn` / `threshold` (options, `defaults` and per-frame) like the CLI does.
- `failOn` / `threshold` in `.framedrift.json` are validated (a typo is a config error, exit 2). Precedence: frame > CLI flag / Action input > `defaults` > built-in.
